# Decisions Log

| # | Decision | Why | Date |
|---|---|---|---|
| 1 | **Everything goes through the Dispatcharr proxy** — never `direct=true` | Provider pins UA (`TiviMate/5.1.6`) and is effectively 1-connection; Kodi's extra probes were stealing the slot and causing 502s | 2026-09-21 |
| 2 | **`max_streams` 1 → 2** | The 1 was Dispatcharr's own cap, not the provider's; it made every zap fail | 2026-09-21 |
| 3 | **Catchup + timeshift OFF** | Provider has zero archive (`tv_archive=1` on 0/15,830) and both are documented Kodi-Omega crash bugs (#499, #760). Time-shifting = Dispatcharr DVR recordings instead | 2026-09-21 |
| 4 | **Curated "Kodi" profile for the box, full lineup for Jellyfin** | 3,590 channels / 71 messy groups was unusable; the client gets a clean 1,669 | 2026-09-21 |
| 5 | **Timezone America/Chicago on box + containers, host stays UTC** | Host runs production stacks; guide was displaying 5 h late because everything defaulted to UTC | 2026-09-26 |
| 6 | **EPG writes go to `ChannelOverride`** | Provider sync rewrites `Channel.*`; overrides are the designed persistence point | 2026-09-26 |
| 7 | **Wrong-region EPG is blanked, not left** | A French schedule on a Mexican channel is worse than a placeholder; needs the `NO GUIDE` dummy because an override of NULL falls back | 2026-09-26 |
| 8 | **No-guide sweep is one-way and skips curated picks** | The original group isn't recorded, so sweeping before the guide settles strands channels; curated picks (RedZone, PPV slots) must stay put | 2026-09-26/27 |
| 9 | **Backup streams over retry tuning** | `MAX_RETRIES`/`RETRY_WAIT_INTERVAL` are in-container constants with no override; data-level failover is persistent and uses Dispatcharr's own mechanism | 2026-09-27 |
| 10 | **Fixture labels from `Stream.name` → `ChannelOverride.name`** | The provider updates stream names as fixtures are assigned; daily cron keeps them fresh | 2026-09-27 |
| 11 | **FLIRC over HDMI-CEC for the remote** | V505-H9 remote is IR-only (manual-verified), FLIRC is cheaper, avoids the LE 12.2 libCEC 7.1.1 regression, and works pre-boot | 2026-09-27 |
| 12 | **Audio stays PCM (passthrough off)** | HDMI sink is `AE_DEVTYPE_PCM` on stereo TV speakers; bitstreaming would kill Kore's volume control for zero gain | 2026-09-26 |
| 13 | **Reflashing rejected as the fix for crashes** | Root causes were catchup+timeshift on an archive-less provider and a client bypassing the proxy — both fixed in place | 2026-09-26 |
| 14 | **User edits live in `ChannelOverride`; scripts are dry-run by default and idempotent** | Every "it silently reverted" incident traced back to writing `Channel.*` | 2026-09-26 |
| 15 | **Provider VOD goes to Jellyfin via the STRM-writing *Xtream Library* plugin, not Kevinjil's `Jellyfin.Xtream`** | Kevinjil's exposes VOD as Jellyfin *channels*, which `jellyfin-kodi` does not sync — Kodi would never see the content. STRM files become native libraries that do sync. Plugin pinned to v1.55.3.0 because v2.0.x failed to load on Jellyfin 10.11 despite claiming ABI 10.11 | 2026-09-29 |
| 16 | **VOD library is a curated English "best of", not the full catalog** | 28.7k movies is unusable to browse and heavy on the provider API; foreign-language/regional, multi-sub and niche shelves are dropped (`scripts/pick-xtream-categories.py`). Widening later is one config change | 2026-09-29 |
| 17 | **Provider PPV slots are wired per-sport into the Kodi profile, unhidden explicitly** | Slots ship `hidden_from_output=True` (silently excluded from the profile M3U) and their names rotate per fixture, so a per-sport resolver (`add-wnba-events.py`) plus `KODI_GROUPS`/`CURATED_GROUPS` entries are required or the next profile rebuild drops them | 2026-09-29 |
| 18 | **Provider API calls are rate-limited by us, not by the plugin defaults** | A first sync across all categories (~11k API calls) tripped a Cloudflare 403 block on the whole IP for ~56 min; live streams kept working. Selection is kept tight and `RequestDelayMs=250`, `SyncParallelism=3` | 2026-09-29 |
| 19 | **Dispatcharr runs on `network_mode: host`** (not `media-net`) | The provider front 403'd this host's IPv4 on *every* endpoint while IPv6 worked; a bridge container has no IPv6 route, so it could only fail. Host networking gives it the host's working IPv6 egress. Jellyfin keeps `http://dispatcharr:9191/...` via an `extra_hosts` alias to the pinned media-net gateway (172.18.0.1). Trade-off: Dispatcharr loses network isolation and 9191 binds directly on the host (it already did) | 2026-10-01 |
| 20 | **Jellyfin also moved to `network_mode: host`** | The Xtream VOD sync talks to the provider directly and was the thing tripping the ban; while Jellyfin stayed bridged it could only use the blocked IPv4. Host networking gives it IPv6 too. `dispatcharr` is aliased to loopback via `extra_hosts`, so the tuner/EPG URLs are unchanged. `media-net` is now only watchstate | 2026-10-01 |
| 21 | **The Xtream VOD sync has no schedule — run it by hand** | It fires thousands of `player_api.php` calls and trips the provider's abuse block (403s our egress, kills live TV). The plugin has no "off" in its dropdown. Trigger via `scripts/sync-vod.sh` / the plugin's *Manual Sync* button. ⚠️ **superseded by #24**: `Manual` still left an hourly interval trigger | 2026-10-01 |
| 22 | **Provider profile `max_streams` 2 → 3** | With 2, one zap already fills the cap (old+new), so any lingering/failed init 503s the next zap. 3 gives headroom; a direct test showed the provider serves 3 concurrent streams | 2026-10-01 |
| 23 | **IPv4-first egress via a mounted `config/gai.conf`** | The blocked address family *flips*: IPv4 banned on 2026-10-01, then **IPv6** banned by 2026-10-03 while IPv4 served (web root 401, live 302). glibc sorts AAAA first, so a host-networked container kept hitting the banned family. `precedence ::ffff:0:0/96 100` forces the A records first. A restart re-breaks streams unless the mount is present | 2026-10-04 |
| 24 | **Xtream sync interval set to 525600 min (1 year) — the only way to stop it** | The plugin's `GetDefaultTriggers()` always returns a trigger: `Daily` → daily; **everything else, incl. `Manual`, → an interval trigger of `SyncIntervalMinutes`**, which defaults to 60 when 0/negative. So #21 only silenced the *daily* line while the sync kept firing **hourly** and re-tripping the ban. Config-only stop = huge interval | 2026-10-04 |
| 25 | **Recover a drained guide by re-running Dispatcharr's own EPG/M3U refresh tasks — do NOT persist `/app/media`** | The programmes had **expired**, not corrupted: the provider's `xmltv.php` is short-horizon and the 6-hourly refresh had been 403ing since the pre-`gai.conf` ban, so the guide aged out. `/app/media` is an `APP_DIRS` path (ephemeral by design, per the image's init script and the official compose which persists only `/data`), so a cache volume is unnecessary. Verified first-party: `refresh_epg_data` → `status=success`, 24,235 future programmes; `refresh_single_m3u_account` → `success`; `verify-stack.sh` healthy | 2026-10-04 |
| 26 | **No hard-coded address family in `config/gai.conf` — the override is removed** | The ban flipped a **third** time: 2026-10-25 IPv4 was 403'd (and `000` on connect) while IPv6 served normally (401 web root, 200 + `video/mp2t` on stream URLs). The `precedence ::ffff:0:0/96 100` line added on 2026-10-04 was therefore pinning every container lookup to the **blocked** family, which is why Dispatcharr stalled at `waiting for buffer to fill: 0/4 chunks` while a direct IPv6 `curl` pulled 25 MB of video. Removing the line restores glibc's RFC 3484 default: AAAA wins when the host holds a global IPv6 address (it does). A **restart** is required, not a reload — glibc caches gai.conf per process. The file now records all three flips and the one-line revert (`precedence ::ffff:0:0/96 100` + `docker restart dispatcharr jellyfin`). Supersedes the "prefer IPv4" half of #23; the *lesson* of #23 (never hard-code a family) stands | 2026-10-25 |
| 27 | **A second subscription (ZQAVO) is wired in as a cross-provider *failover*, never a replacement** | Every source on a channel came from one subscription (STRONG8K), so a provider-wide outage killed the primary **and** all its failovers at once — exactly what happened on 2026-10-25 (IPv4 403'd, then 502 on both families for hours). The new sub (33,614 live streams / 725 categories, `max_connections: 1`) is imported with a **tight group selection** — 13 `\|US\|` categories → 1,529 streams, not all 725 — because provider API abuse blocks are the documented failure mode. `scripts/add-cross-provider-failover.py` attaches its feeds at the **highest** `ChannelStream.order` on 22 curated channels. The mapping is an explicit name table, deliberately **not** fuzzy: `add-backup-streams.py`'s normalisation had attached `NFL  \| 4k - SNF 8:20pm Chiefs at Seahawks` as the "backup" for NFL Network, so a failover would have silently shown a different game. That audit was finished here — 4 wrong-fixture links removed, and those NFL Network channels given the new provider's *correct* feed instead (so they are no longer single-source). Trade-off: `max_connections: 1` means the new provider cannot serve two channels at once, so it is failover-only | 2026-10-25 |
| 28 | **Stream-quality changes are audit-first and conservative, never automatic** | Provider names lie (`4K` can be 720p60, `RAW` can be corrupt), and Dispatcharr has no built-in best-source selector. `scripts/audit-stream-quality.py` probes one stream at a time through the stream-specific proxy path; `scripts/apply-stream-quality.py` only reorders sources that are already attached to the channel, requires the candidate to normalise to the same channel identity and region, never promotes event slots, and always leaves ZQAVO deepest. This keeps quality gains reversible and avoids silently swapping to a different feed/language | 2026-10-29 |
| 29 | **The Telegram ↔ Cline bridge is a containerized `cline connect telegram`, not custom bot code** | Cline CLI 3.x ships a first-party Telegram connector (polling, allowlist, tools, act mode); writing our own bot would duplicate it. The container needs host networking (mDNS `k5320.lan`, LAN reach), a dedicated hub port (25464) because the host's own hub owns 25463, jq in the image (the allowlist hook shells out to it), and provider auth seeded from the host's read-only `~/.cline` into a writable state volume. Bot token + allowlisted user id live only in `.env` | 2026-10-31 |
| 30 | **ZQAVO per-fixture event streams are wired by hand onto VIX slot channels (for now)** | The `:Nbc Sports NN`/`:Peacock Event NN` streams arrive as raw `Stream` rows with no channel, invisible to every channel/guide search — the exact trap the Telegram agent hit asking for Liga MX. The disabled VIX PREMIUM DEPORTES slots already in the Kodi profile are natural one-night hosts. A generic `wire-event-stream.py` is queued to replace the one-off | 2026-10-31 |
| 31 | **STRONG8K "US (Peacock 0NN)" event slots are hand-wired per night, same pattern as #30 (membership + unhide + fixture override)** | EPL matchweeks can be Peacock-only — zero EPG rows anywhere — while these slots exist as hidden+disabled channels with stale names but a *current* order-0 fixture stream; the one-night fix is enabling + unhiding + a fixture `ChannelOverride.name` until the generic `wire-event-stream.py` exists | 2026-11-07 |
